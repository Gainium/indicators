# 002. McGinley Dynamic indicator — plan

Implements [specs/002.mcginley-dynamic-indicator.md](../specs/002.mcginley-dynamic-indicator.md).

## Build order

1. `src/McGinley/McGinley.ts` — `LightIndicator<number, number>` subclass,
   single `Float64Array` state slot holding the previous `mg` value, no
   child indicator (per spec §4).
2. Factory registration (spec §1/§4 require full registration — not a
   filter):
   - `src/types/config.ts`: `IndicatorEnum.mg = 'MG'`,
     `IndicatorConfig` member `{ type: IndicatorEnum.mg; mgLength: number }`.
   - `src/factory/create.ts`: `case IndicatorEnum.mg: return new McGinley(config.mgLength ?? 14)`.
   - `src/factory/warmup.ts`: `case IndicatorEnum.mg`.
   - `src/factory/feed.ts`: add `McGinley` to the existing close-only
     numeric dispatch branch (same shape as `EMA`/`SMA`/etc.) — no new
     branch needed.
   - `src/index.ts`: `export * from './McGinley/McGinley'`.
3. `package.json` + `CHANGELOG.md` version bump.

## Contract decisions the spec left open (§3)

- **Warmup candle count.** Decision: `config.mgLength + 100`. Rationale:
  the formula is valid from bar 1, but the same "generous stabilization
  buffer" reasoning the `ma` case already uses (`interval + 300`) applies
  here — the first few bars of a recursive adaptive average are a poor
  read on its steady-state behaviour. `+100` rather than `+300` because
  McGinley's feedback term (`(price/mg)^4`) converges faster than a linear
  EMA blend does; there is no ATR-style secondary indicator warming up
  underneath it (unlike `LongWick`'s `+201` from its nested `ATR(200)`).
- **Not an alias.** Confirmed in spec §3 — gets its own `IndicatorEnum.mg`
  entry and class, not an `MAEnum` variant.

## Blast Radius

1. **Other call sites of the factory functions** — grepped
   `createIndicator`/`getWarmupCandles`/`feedCandle` across the checked-out
   gainium repos. Real consumers: `app-sh` (`src/indicators/{service,worker}.ts`),
   `app/core` (the same files, mirrored via the `core/` submodule),
   `market-archive` (`src/indicators/runner.ts`,
   `src/scripts/smokeIndicatorRpc.ts`). All three are **factory-driven** —
   once this repo's version is published and each consumer bumps its
   `@gainium/indicators` dependency, they pick up McGinley with **no new
   per-indicator code** on their side (this is the whole point of the
   factory, per the new-indicator-integration skill's mental model).
   `app-sh` is in this PR's scope (separate spec in that repo);
   `market-archive` and `app` (outer) are out of scope for this
   demonstration per the user's explicit instruction, but nothing in this
   change requires touching them — flagging, not skipping a required step.
2. **`core/` submodule** — N/A, this repo has no `core/` submodule; it *is*
   the shared package other repos' `core/`s depend on.
3. **Contract surface this repo's `CLAUDE.md` documents as owned** —
   `CLAUDE.md`'s "Coupling" section: *"A change to indicator output
   (values, `IndicatorEnum`, warmup math) silently changes bot signals,
   backtests, and archived indicator results across every consumer."*
   This change adds a new `IndicatorEnum` value and new factory branches —
   additive, not a change to any existing indicator's enum value or
   output shape, so no existing consumer's behaviour changes until it
   explicitly opts in by sending `config.type === IndicatorEnum.mg`.
4. **`@gainium/backtester`** — does **not** consume this repo's factory
   (per the new-indicator-integration skill: it hand-wires each indicator
   with its own duplicated type set). It needs its own separate PR
   (`src/types.ts` + `indicatorLoader.ts` + strategy branches) before a bot
   using McGinley can backtest. Explicitly out of scope here (user asked
   for `indicators` + `main-dash-sh` + `app-sh` only) — **naming the gap**:
   until that PR lands, a bot configured with `IndicatorEnum.mg` will fail
   or silently no-op in backtests. Flag this to the user before treating
   the 3-repo PR set as shippable.
5. **Other tests exercising this path** — none yet; `test/placeholder.spec.ts`
   is unrelated scaffolding, left untouched.
